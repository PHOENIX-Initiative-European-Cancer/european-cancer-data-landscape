# National FHIR, oncology and terminology landscape: Germany, Austria, Switzerland, Netherlands, Belgium

Survey for the editors of the HL7 Europe Common Cancer Data Model IG. Facts only, sources checked 2026-11-18. Items marked "not found" could not be verified from a primary source.

## Germany

1. **Base IG.** HL7 Deutschland Basisprofile DE (R4), package `de.basisprofil.r4`, FHIR 4.0.1. Latest final release 1.6.0 (after 1.6.0-ballot and 1.6.0-ballot2; profiles dated 2025-12-23); earlier stable line 1.5.4 (2025-06-17). Publisher HL7 Deutschland e.V., Technisches Komitee FHIR. https://get-ig.org/de.basisprofil.r4 ; https://simplifier.net/basisprofil-de-r4
2. **Oncology.** MII Kerndatensatz Modul Onkologie, package `de.medizininformatikinitiative.kerndatensatz.onkologie`, FHIR 4.0.1, canonical https://www.medizininformatik-initiative.de/fhir/ext/modul-onko. Latest release 2026.0.3; 2027.0.0-ballot built 2026-09-14; 2026.0.0-ballot IG dated 21.08.2025. Implements the oBDS (package description; 2025 release notes name oBDS 3.0.2). mCODE is discussed as an influence only; the IG states mCODE rests on US Core and is "nicht direkt anwendbar" in Germany. https://get-ig.org/de.medizininformatikinitiative.kerndatensatz.onkologie ; https://www.medizininformatik-initiative.de/Kerndatensatz/KDS_Onkologie/MIIIGModulOnkologie-BezugZuInternationalenStandards.html . Also: "Onkologische FHIR-Basisprofile für Deutschland" v1.0.0 listed on gematik INA, work dormant since 2022 commenting; harmonisation to be coordinated by gematik KIG from 2025. https://www.ina.gematik.de/detailansicht/standard/onkologische-fhir-basisprofile-fuer-deutschland-845 ; https://www.medizininformatik-initiative.de/Kerndatensatz/KDS_Onkologie/MIIIGModulOnkologie-BezugZuNationalenStandards.html
3. **Registry standard.** Einheitlicher onkologischer Basisdatensatz (oBDS) XML interface, published in Bundesanzeiger 12.07.2021. XML schema V3.0.5 published 24.10.2025 (adds TNM 9th edition); V3.1.0 published 14.10.2026 (new DKKR module); a further version adding ICD-O-4 2026, TNM 9 and CTCAE 6.0 is planned for acceptance by the Landeskrebsregister from 01.04.2027. Maintained by ADT and Deutsche Krebsregister e.V. (ex GEKID) with Plattform § 65c in the AG Daten under § 65c SGB V; reports go to the state clinical cancer registries. https://basisdatensatz.de/xml-schnittstelle ; https://basisdatensatz.de/
4. **Terminologies.** SNOMED CT member since January 2021, NRC BfArM, National Edition semi-annual on 15 May and 15 November (https://www.snomed.org/members/germany ; https://www.bfarm.de/EN/Code-systems/Terminologies/SNOMED-CT/National-Edition/_node.html). ICD-10-GM 2026 (final 18.09.2025) and OPS 2026 (24.10.2025), BfArM (https://www.bfarm.de/EN/News/News-from-the-divisions/Code-systems-news/_node.html). ICD-O-3 Zweite Revision 2019, in force since 01.01.2020 (https://www.bfarm.de/DE/Kodiersysteme/Klassifikationen/ICD/ICD-O-3/_node.html). LOINC: BfArM German translation shipped in LOINC 2.79+ (https://www.bfarm.de/EN/Code-systems/Terminologies/LOINC-UCUM/LOINC-and-RELMA/German-Translation/_node.html). ATC: amtliche ATC/DDD-Klassifikation 2026, BfArM (https://bfarm.de/EN/Code-systems/Classifications/ATC/_node.html). TNM: UICC 8th edition in registry use, 9th edition values added in oBDS 3.0.5. Terminology server: Zentraler Terminologieserver, https://terminologien.bfarm.de , BfArM with gematik, FHIR API, launched Dec 2024 (https://www.bfarm.de/EN/Code-systems/Services/Terminologyserver/_node.html).
5. **People.** TC FHIR HL7 Deutschland led by Simone Heckmann (term to Dec 2026) (https://hl7.de/technische-komitees/fhir/); Basisprofile top GitHub contributors Alexander Zautke, Patrick Werner (https://github.com/hl7germany/basisprofil-de-r4). MII Onkologie contacts Thomas Debertshäuser and Sylvia Thun (BIH at Charité), Martin Boeker (DIFUTURE), Karoline Buckow and Franziska Klepka (TMF); authors include Christian Gulden (BZKF), Jori Kern (DKFZ), Julian Saß (BIH), Yuan Peng (TU Dresden) (https://www.medizininformatik-initiative.de/Kerndatensatz/KDS_Onkologie/MIIIGModulOnkologie.html).

## Austria

1. **Base IG.** HL7 Austria FHIR Core IG. R5: `hl7.at.fhir.core.r5` 2.0.0, STU2, FHIR 5.0.0, generated 2025-01-24, current published; 2.1.0 (STU3) only as CI build. R4: `hl7.at.fhir.core.r4` 2.0.0, STU2, FHIR 4.0.1, generated 2025-01-27. Publisher HL7 Austria, TC FHIR. https://fhir.hl7.at/HL7-AT-FHIR-Core-R5/ ; https://fhir.hl7.at/HL7-AT-FHIR-Core-R4/ ; registry https://fhir.hl7.at/
2. **Oncology.** None. The HL7 Austria registry lists only Core R4/R5, TC-FHIR-AG-Scheduling-R5 and ELGA-AustrianPatientSummary-R4; ELGA is "mainly based on HL7 CDA" (https://fhir.hl7.at/ ; https://fhir.hl7.at/HL7-AT-FHIR-Core-R5/). Cancer registry FHIR profile set: not found.
3. **Registry standard.** Österreichisches Nationales Krebsregister, run by Statistik Austria under Krebsstatistikgesetz 1969 and Krebsstatistikverordnung 2019 (BGBl. II Nr. 124/2019). Hospitals must report exclusively electronically and structured via a secured interface provided by Statistik Austria, using the encrypted identifier vbPK-AS, within three months. Transmission channels: web form via eQuest, file upload via eQuest, or SFTP file transfer (Statistik Austria Standarddokumentation Krebsstatistik, §2.1.7, https://www.statistik.at/fileadmin/shared/QM/Standarddokumentationen/B_2/std_b_krebsstatistik.pdf); named XML/CSV schema: not found (verified 2026-11-19). https://www.statistik.at/statistiken/bevoelkerung-und-soziales/gesundheit/krebserkrankungen ; https://ris.bka.gv.at/Dokumente/BgblAuth/BGBLA_2019_II_124/BGBLA_2019_II_124.pdf ; https://www.statistik.at/fileadmin/publications/Krebserkrankungen_Berichtsjahr-2024_bf.pdf
4. **Terminologies.** SNOMED CT member since March 2019 (37th member), NRC ELGA GmbH; Austria Extension via SNOMED Managed Service, releases e.g. Nov 2025 (on Nov 2025 International Edition) and May 2026 (https://www.snomed.org/news/austria-introduces-nationwide-standard-of-clinical-terminology-with-membership-in-snomed-international ; https://conf.spaces.snomed.org/wiki/spaces/RMT/pages/353370146). ICD-10 BMSGPK 2026 in use since 01/2026; 2027 version registered (https://www.gesundheit.gv.at/OID_Frontend/oid-static/1/2/40/0/34/5/231.html). Registry coding: ICD-O-3 Revision 2 since 2020, TNM UICC 8th edition (Statistik Austria report above). LOINC: ELGA LOINC guideline V1.03 (2017), LOINC German Austria Edition 2.77 (https://www.elga.gv.at/fileadmin/user_upload/Dokumente_PDF_MP4/CDA/Leitfaden_LOINC_Anwendung_in_ELGA_V1.03.pdf). Drug coding: ELGA e-Medikation uses the Pharmazentralnummer (PZN) from the ASP-Liste plus ATC codes; the BASG keeps the register of authorised medicinal products (https://fhir.hl7.at/r4-ELGA-e-Medikation-main/StructureDefinition-at-elga-emed-medication-medikation-definitions.html) (verified 2026-11-19). Terminology server: TerminoloGit, https://termgit.elga.gv.at , ELGA GmbH, FHIR endpoint "FHIR-tx-at", replaced the old ELGA server on 1 Oct 2022 (https://www.gesundheit.gv.at/service/professional/it-services/terminologieserver.html).
5. **People.** TC FHIR authors page (dev build; the published 2.0.0 IG has no authors page and the dev page is not retrievable by automated fetch, checked 2026-11-19) names Anna Lin (TC FHIR Lead, FH OÖ), Reinhard Egelkraut (CGM), Oliver Krauss (FH OÖ) (https://dev-tergi.elga.gv.at/r5-core-70-Apply-Template-for-Base-IGs/authors.html); HL7 Austria chair Alexander Mense (https://hl7.eu/affiliate_at.html). Core R5 GitHub top contributors gabriel0316, oliver-krauss, regelkraut (https://github.com/HL7Austria/HL7-AT-FHIR-Core-R5). SNOMED NRC head Stefan Sabutsch (2019 press release above).

## Switzerland

1. **Base IG.** CH Core (R4), package `ch.fhir.ig.ch-core`, FHIR 4.0.1, canonical http://fhir.ch/ig/ch-core/ImplementationGuide/ch.fhir.ig.ch-core. Last STU release 6.0.0 (STU 6, 2025-12-16); 7.0.0-ballot published 2026-06-10, STU ballot 4 Aug to 30 Sep 2026. Publisher HL7 Switzerland. https://fhir.ch/ig/ch-core/6.0.0/index.html ; https://fhir.ch/ig/ch-core/index.html
2. **Oncology.** CH CRL (Cancer Registration Law) IG, package `ch.fhir.ig.ch-crl` 0.9.0, STU Draft, FHIR R4, publisher Bundesamt für Gesundheit (BAG), generated 2022-02-04; specifies the "Austauschformat KRG" exchange format (cancer report logical model, FHIR document, profiles for patient, diagnosis, TNM, procedures), built on CH Core; terminology page lists NKRS code systems (ICD-O-3 behaviour, grade, laterality, TNM stage group, Ann Arbor, Binet). mCODE: the npm package ch.fhir.ig.ch-crl 0.9.0 contains no reference to mCODE; dependencies are hl7.fhir.r4.core 4.0.1 and ch.fhir.ig.ch-core 2.0.0 (https://fhir.ch/ig/ch-crl/package.tgz) (verified 2026-11-19). https://fhir.ch/ig/ch-crl/index.html ; https://fhir.ch/ig/ch-crl/terminology.html . No other oncology IG on fhir.ch found.
3. **Registry standard.** Krebsregistrierungsgesetz in force 1 Jan 2020; reports go to the cantonal cancer registries and the Kinderkrebsregister; the Nationale Krebsregistrierungsstelle (NKRS) is run by the NICER foundation, Zurich, mandated since 2018. Format: "Austauschformat KRG", FHIR-based, developed by BAG; normative spec released 8 Jan 2020 (PDF 10 Jan 2020), use case 1a (embedded PDF plus minimal data) and 1b (structured data, first tranche of 30 variables); adoption voluntary; BAG offers FHIR test-file validation. NKRS data structure: variable lists v1.5, "Einführung Datenstruktur" v1.1. https://www.bag.admin.ch/de/datenformat-krebsregistermeldung ; https://www.nkrs.ch/de/meldepflicht/informationen-fuer-it-partner ; https://www.nkrs.ch/de/ueber-uns ; https://www.nkrs.ch/de/downloads
4. **Terminologies.** SNOMED CT member since January 2016, NRC eHealth Suisse; Swiss Extension released each June/July and December (June 2025, Dec 2025) (https://www.snomed.org/members/switzerland ; https://conf.spaces.snomed.org/wiki/spaces/RMT/pages/424738850). ICD-10-GM is used for SpiGes inpatient coding, maintained for Switzerland by BFS; from ICD-10-GM 2026 each German version is adopted one year later because of the French and Italian translations, so coding year 2026 uses ICD-10-GM 2024 (Swiss supplement of 2024-10-31) and coding year 2027 uses ICD-10-GM 2026 (Swiss supplement 2026-10-27); CHOP 2027 published 2026-07-30 (https://statistik.admin.ch/de/daten-statistiken-verstehen/nomenklaturen/medkk/instrumente-medizinischen-kodierung, read in a browser) (verified 2026-11-19). CHOP 2026 in force 1 Jan 2026 (https://ckan.opendata.swiss/dataset/schweizerische-operationsklassifikation-chop10). ICD-O-3 and UICC TNM: the NKRS Data Dictionary Basic Variables v1.5 (valid 01.01.2026) records the ICD-O version (variable 3.2) and the UICC TNM edition (variable 4.1) per case instead of fixing one edition (https://www.nkrs.ch/upload/downloads/Forschende/Datenstruktur/Datenstrukturv15/Basisdatenv15/A_DataDictionary_BasicVariables_v1.5_01.01.2026.pdf) (verified 2026-11-19). LOINC: used in CH LAB-Order 3.0.0 (2025-12-16) and CH LAB-Report (1.0.0 trial-use, 3.0.0 ballot) (https://fhir.ch/ig/ch-lab-order/index.html ; https://fhir.ch/ig/ch-lab-report/usecases-en.html) (verified 2026-11-19). CH Term 3.4.0 (STU, 2026-06-10) carries Swiss code systems and value sets (https://fhir.ch/ig/ch-term/index.html). Terminology server: https://tx.fhir.ch/r4 , HL7 Switzerland (listed in the FHIR tx-servers registry https://fhir.github.io/ig-registry/tx-servers.json); no national government terminology server, eHealth Suisse position paper recommends one (https://www.e-health-suisse.ch/payload/api/documents/file/Positionspapier_Basisterminologien_V1.pdf).
5. **People.** CH Core managed by HL7 Switzerland TC FHIR (tc@hl7.ch); top GitHub contributors Oliver Egger (ahdis) and Michaela Ziegler (https://github.com/hl7ch/ch-core). CH CRL owner BAG, Abteilung Prävention nichtübertragbarer Krankheiten (krebsregistrierung@bag.admin.ch); named editors: not found (package.json lists only Bundesamt für Gesundheit BAG as author and maintainer, checked 2026-11-19).

## Netherlands

1. **Base IG.** nl-core (FHIR R4 profiles for zib release 2020), package `nictiz.fhir.nl.r4.nl-core`, FHIR 4.0.1, publisher Nictiz, CC0. No non-beta release exists; latest 0.12.1-beta.1 (2026-08-25), 0.12.0-labtrial.1 (2025-12-12), 0.12.0-beta.4 (2025-09-30). Companion package `nictiz.fhir.nl.r4.zib2020`. Nictiz FHIR R4 IG 1.0.4. https://get-ig.org/nictiz.fhir.nl.r4.nl-core ; https://informatiestandaarden.nictiz.nl/wiki/FHIR:V1.0_FHIR_IG_R4
2. **Oncology.** IKNL "FHIR Implementatiegids voor de Nederlandse Kankerregistratie", package `iknl.fhir.nl.r4.ncr-ehr`, FHIR 4.0.1, latest 1.4.2, author Integraal Kankercentrum Nederland; CI build https://build.fhir.org/ig/IKNL/NkrIG/ ; source https://github.com/IKNL/NkrIG ; package https://get-ig.org/iknl.fhir.nl.r4.ncr-ehr . Depends on nl-core/zib2020 0.12.0-beta.4; the `hl7.fhir.us.mcode` dependency is commented out in sushi-config, so mCODE is not reused (https://build.fhir.org/ig/IKNL/NkrIG/branches/main/failure/sushi-config.yaml). Implements the NKR EHR submission dataset (nl-core Patient, EpisodeOfCare, Procedure, Problem, lab result linked to tumour). zib TNMTumorClassificatie v4.1 (2025-04-25) (https://www.zibs.nl/wiki/TNMTumorClassificatie-v4.1(2024NL)). PALGA FHIR: IKNL package iknl.fhir.nl.r4.palga 1.0.1 (FHIR R4) defines profiles for incidence notifications and protocol data sent by PALGA to the NKR (https://get-ig.org/iknl.fhir.nl.r4.palga) (verified 2026-11-19).
3. **Registry standard.** Nederlandse Kankerregistratie (NKR), run by IKNL since 1989; data collected by IKNL data managers from hospital records after signalling via PALGA and hospital registrations (DHD); automated nightly EHR extraction via the FHIR IG in 20 hospitals; 2024 figures about 125,000 partly manual and 60,000 fully automated records. No mandated XML format; per-diagnosis "NKR-itemset". Coding ICD-O-3 and UICC TNM 8th edition. https://iknl.nl/nkr ; https://iknl.nl/en/ncr ; https://www.oncologie.nu/nieuws/validatie-van-geautomatiseerde-realtime-gegevensuitwisseling-van-epds-naar-nkr/ ; https://richtlijnendatabase.nl/richtlijn/colorectaal_carcinoom_crc/pathologie_bij_crc/tnm_bij_crc.html
4. **Terminologies.** SNOMED CT charter member 2007, NRC Nictiz, monthly NL Edition (Nov 2025 release: 391,305 active concepts) (https://www.snomed.org/members/netherlands ; https://conf.spaces.snomed.org/wiki/spaces/RMT/pages/353370340). ICD-10: Dutch translation by WHO-FIC Collaborating Centre at RIVM, latest book edition ICD-10 2021 (https://whofic.nl/downloads-en-links/icd-10). ICD-O-3 Dutch translation hosted by RIVM (https://www.rivm.nl/media/WHO-FIC/ICD-O-3.pdf). LOINC via Nederlandse Labcodeset, currently on LOINC 2.83 (2026-08-19) (https://labterminologie.nl/). National drug code: G-Standaard, maintained by Z-Index (https://www.z-index.nl/g-standaard) (verified 2026-11-19). Terminology server: Nationale Terminologieserver (NTS), Nictiz, Ontoserver, hosting SNOMED, LOINC, ICD-10, Labcodeset (https://ontoserver.csiro.au/site/nictiz-national-terminology-server/ ; https://www.nictiz.nl/document/beginnershandleiding-nationale-terminologieserver-nts-10-definitiefpdf).
5. **People.** IKNL NkrIG GitHub contributors jeroen-trompetter, basharmsen, Harmke Koning (https://github.com/IKNL/NkrIG). Nictiz nl-core: top GitHub contributors to Nictiz/Nictiz-R4-zib2020 are pieter-edelman-nictiz, jd-nictiz and ArdonToonstra (https://github.com/Nictiz/Nictiz-R4-zib2020) (verified 2026-11-19).

## Belgium

1. **Base IG.** eHealth Platform Federal Core Profiles / HL7 Belgium Core, package `hl7.fhir.be.core`, FHIR R4 (R4 and R4B packages), canonical https://www.ehealth.fgov.be/standards/fhir/core/ImplementationGuide/hl7.fhir.be.core. Current published 2.2.0 (Release, STU1, package built 19 Aug 2026); previous 2.1.2 (30 Aug 2024). Publisher eHealth Platform. Transversal Clinical Core `hl7.fhir.be.core-clinical` 1.4.0 current. https://www.ehealth.fgov.be/standards/fhir/core/2.2.0/index.html ; https://get-ig.org/hl7.fhir.be.core ; https://www.ehealth.fgov.be/standards/fhir/core-clinical/index.html
2. **Oncology.** No published national oncology FHIR specification. "Belgian Cancer Registry on FHIR" (package `be.fhir.bcr` 0.1.0, FHIR 4.0.1, draft/experimental, dated 2026-06-03) is an individual developer's local development build by Axel Vanraes (Tiro.health) on GitHub Pages, not a published eHealth Platform or HL7 Belgium specification: its stated canonical https://www.ehealth.fgov.be/standards/fhir/registries/bcr/ returns 404, the package is not on Simplifier or packages.fhir.org, and no hl7-be repository contains it; the copyright line names eHealth Platform Belgium only because the build uses that publisher template (verified 2026-11-19). Logical models of the BCR registration form Bijlage 55 plus three supplements (breast, MOC, follow-up), the Cancer in Belgium research dataset (metadata v2, May 2025) and cyto-histopathology screening samples; 23 CodeSystems, 33 ValueSets, all draft pending BCR review. mCODE: the npm package be.fhir.bcr 0.1.0 contains no reference to mCODE; dependencies are hl7.fhir.r4.core 4.0.1, hl7.terminology.r4 7.1.0 and hl7.fhir.uv.extensions.r4 5.2.0 (https://axelv.github.io/bcr/package.tgz) (verified 2026-11-19). https://axelv.github.io/bcr/index.html ; https://api.github.com/users/axelv . HL7 Belgium terminology IG (`hl7.fhir.be.terminology` 1.0.0) has an experimental OncologyPatientCodes value set (https://build.fhir.org/ig/hl7-be/terminology/en/ValueSet-OncologyPatientCodes.html).
3. **Registry standard.** Belgian Cancer Registry (Stichting Kankerregister / Fondation Registre du Cancer), Brussels. Hospitals with oncological care programmes submit via the WBCR web application or batch extraction, form Bijlage 55 of the RIZIV Verordening of 28-07-2003, amended 15-12-2025, within 4 to 6 months of incidence. healthdata.be collection BCR_Cancer (v1.1, CSV) accepts ICD-O-3 topography and morphology and official UICC TNM codes. TNM edition: not found (kankerregister.org registration pages not retrievable by automated fetch, 2026-11-19). Official batch file specification: not found (same). https://kankerregister.org/en/ ; https://axelv.github.io/bcr/StructureDefinition-bcr-cancer-registration-form.html ; https://dcd.healthdata.be/en/collection/BCR_Cancer/ ; https://www.riziv.fgov.be/SiteCollectionDocuments/formulier_verordening20030728_bijlage_55.docx
4. **Terminologies.** SNOMED CT: NRC is the Terminology Centre of FPS Public Health; first Belgian release March 2018; joined IHTSDO in 2013 according to a 2013 CliniSys presentation (secondary source, https://wiki.ihe.net/uploads/2/23/LAB_Tokyo_Semantic_Migom.pdf); listed as member by Dec 2016 (https://en.wikipedia.org/wiki/International_Health_Terminology_Standards_Development_Organisation) (verified 2026-11-19); snomed.org states six-monthly releases while SNOMED release notes show monthly releases since Nov 2024 (Dec 2025, Feb 2026, June 2026) (https://www.snomed.org/members/belgium ; https://conf.spaces.snomed.org/wiki/spaces/RMT/pages/476184610). ICD-10-BE (Belgian ICD-10-CM/PCS, mandatory since 2015 discharges); latest handbook found: version 2023; coding tool icd10be.health.belgium.be (https://www.health.belgium.be/sites/default/files/uploads/fields/fpshealth_theme_file/passage_a_licd-10-be_version_2023_et_au_apr-drg_version_v40.0.pdf). ICD-O-3 for registry coding (healthdata.be above). LOINC: HL7 Belgium lab IG requires LOINC per the subset defined by FPS Health (https://build.fhir.org/ig/hl7-be/lab/qa-ipreview.html) (verified 2026-11-19). Drug coding: SAM (Authentic Source of Medicines) with CNK product codes (NamingSystem be-ns-cnk-codes) and an ATC-to-CNK mapping published by FPS Health (https://www.ehealth.fgov.be/standards/fhir/medication/en/NamingSystem-be-ns-cnk-codes.html ; https://www.ehealth.fgov.be/standards/kmehr/en/tables/atc-codes) (verified 2026-11-19). Terminology server: Ontoserver 6.25.1 at https://apps.health.belgium.be/ontoserver/fhir , publisher FPS VVVL (FHIR metadata), used as authoritative SNOMED server by Belgian IGs (https://ehealth.fgov.be/standards/fhir/core-clinical/qa-txservers.html).
5. **People.** HL7 Belgium chair Jose Costa Teixeira (https://hl7.eu/affiliate_be.html ; GitHub costateixeira); hl7-be/core top contributor Bart Decuypere (eHealth Platform) (https://github.com/hl7-be/core); BCR on FHIR author Axel Vanraes, Tiro.health, Ghent (https://api.github.com/users/axelv).
